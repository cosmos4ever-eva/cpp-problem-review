## 题意

给出多次区间查询。每次给出两个正整数 `L` 和 `R`，求闭区间 `[L,R]` 内所有质数的和。

查询上界不超过 `10^7`。

## 核心思路

先筛出不超过 `10^7` 的质数，再建立质数前缀和：

```text
prefix_primes[x] = 不超过 x 的所有质数之和
```

于是闭区间 `[L,R]` 中的质数之和为：

```cpp
prefix_primes[R] - prefix_primes[L-1]
```

预处理完成后，每次查询只需要 `O(1)` 时间。

## 为什么数组要多开一位

查询值可能等于 `10000000`，因此这个下标必须存在：

```cpp
vector<long long> prefix_primes(10000001);
```

长度为 `10000001` 时，有效下标是 `0...10000000`。如果只创建 `10000000` 个元素，最大有效下标是 `9999999`，查询上界时就会越界。

多出的下标 `0` 还让 `L = 1` 时的表达式 `prefix_primes[L-1]` 合法。

## 区间和为什么使用 `L - 1`

`prefix_primes[R]` 包含所有不超过 `R` 的质数，`prefix_primes[L-1]` 包含所有严格小于 `L` 的质数。两者相减后，恰好保留闭区间 `[L,R]`。

如果错误地写成：

```cpp
prefix_primes[R] - prefix_primes[L]
```

当 `L` 本身是质数时，会把它一起减掉。例如 `[2,3]` 应得到 `2 + 3 = 5`，错误公式只能得到 `3`。

## 为什么使用 `long long`

单个质数可以用 `int` 保存，但大量质数的和可能超过 `int` 的范围。因此：

```cpp
long long sum;
vector<long long> prefix_primes;
```

累计变量和前缀和数组都必须使用 `long long`，否则会发生整数溢出。

## 解法一：按照质数区间成段填充

两个相邻质数 `primes[i-1]` 和 `primes[i]` 之间没有新质数，因此这一段中所有位置的前缀质数和相同：

```cpp
for(int j = primes[i-1];j < primes[i];j++){
    prefix_primes[j] = sum;
}
sum += primes[i];
```

这种写法需要特别处理最后一段。循环依靠“下一个质数”触发上一段的填充，但最后一个质数后面没有新的质数，所以必须补充：

```cpp
for(int j = primes.back();j <= 10000000;j++){
    prefix_primes[j] = sum;
}
```

否则从最后一个质数到 `10000000` 的前缀和会保持初始值 `0`。

## 解法二：逐个位置递推

也可以从 `1` 到上界逐个计算：

```cpp
for(int i = 1;i <= MAXN;i++){
    preSum[i] = preSum[i-1];
    if(isPrime[i]){
        preSum[i] += i;
    }
}
```

每个位置先继承前一个位置的前缀和；如果当前位置是质数，再把它加入。这种写法不需要单独处理最后一段，含义也更直接。

## 复杂度

- 筛法预处理只执行一次。
- 建立前缀和需要 `O(MAXN)` 时间。
- 每次区间查询只需 `O(1)` 时间。
- `long long` 前缀和数组需要 `O(MAXN)` 空间，在 `10^7` 个元素时约占 `80 MB`。

## 主要易错点

1. 数组长度应为最大下标加一，例如需要访问 `10000000` 时，应创建 `10000001` 个元素。
2. 闭区间 `[L,R]` 的和是 `prefix_primes[R] - prefix_primes[L-1]`，不能减去 `prefix_primes[L]`。
3. 质数的累计和可能超过 `int` 范围，累计变量和前缀数组都要使用 `long long`。
4. 按相邻质数之间的区间成段赋值时，必须单独填充最后一个质数到查询上界的区间。
5. 逐个位置递推时，每个位置先继承 `preSum[i-1]`；当前位置是质数时再加上 `i`，这种写法不需要单独处理末尾。
