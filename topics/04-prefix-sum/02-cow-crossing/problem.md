# 02 奶牛过马路

- 总题号：013
- 日期：2026-09-08
- 类型：排序、前缀最大值、后缀最小值、结构体
- 状态：AI 辅助完成
- 建议复习：2026-09-09
- 原题：[Sunnywhy](https://sunnywhy.com/camp/3415/model/3591?itemId=3574)

## 题意

每头奶牛从马路一侧的坐标 `a` 走到另一侧的坐标 `b`。若一头奶牛的路径不与任何其他奶牛的路径相交，它就是安全的。求安全奶牛的数量。

题目保证所有 `a` 互不相同，所有 `b` 也互不相同。

## 核心思路

先按照 `a` 从小到大排序。排序后，奶牛在马路一侧的相对次序已经确定，路径相交问题就转化成了另一侧坐标 `b` 的次序问题。

对于第 `i` 头奶牛：

- 它不能与左边的奶牛相交，因此它的 `b` 必须大于左边所有奶牛的 `b`；
- 它不能与右边的奶牛相交，因此它的 `b` 必须小于右边所有奶牛的 `b`。

因此，可以从左向右维护 `b` 的前缀最大值，并预处理从当前位置到结尾的后缀最小值。由于所有 `b` 互不相同，当前奶牛安全的判断可以写成：

```cpp
cows[i].b == prefix_max && cows[i].b == suffix_min[i]
```

也就是说，排序把二维路径相交问题转化成了对 `b` 序列的“前缀最大值 + 后缀最小值”判断。

## 第一头奶牛的边界

主循环从 `i = 1` 开始，因此没有判断第一头奶牛。第一头奶牛左边没有其他奶牛，它只需要保证自己的 `b` 小于右边所有奶牛的 `b`，也就是它的 `b` 是整个序列的最小值：

```cpp
if(cows[0].b == suffix_min[0]) cnt++;
```

不要写成 `suffix_min[0] < suffix_min[1]`。虽然在 `N >= 2` 且 `b` 互不相同时它能表达相同含义，但 `N == 1` 时会访问不存在的 `suffix_min[1]`。

## 数据结构

每头奶牛的 `a` 和 `b` 描述同一条路径，排序时必须始终保持这两个数据的对应关系。因此使用结构体保存一头奶牛，再使用 `vector<Node>` 保存全部奶牛：

```cpp
struct Node{
    int a;
    int b;
};

vector<Node> cows(N);
```

输入时直接写入 `cows[i].a` 和 `cows[i].b`。`vector<Node> cows(N)` 已经创建了 `N` 个元素，不需要再使用 `push_back`，否则会在原有 `N` 个元素后面继续添加。

后缀最小值只需要保存一个整数，因此使用 `vector<int> suffix_min(N)`。创建后应通过下标赋值：

```cpp
suffix_min[N-1] = cows[N-1].b;
```

不能再写 `int suffix_min[N-1] = ...`，因为这会尝试重新声明一个同名数组，而不是给 `vector` 的元素赋值。

## 复杂度

- 时间：排序为 `O(N log N)`，前后缀扫描为 `O(N)`。
- 空间：`O(N)`，用于保存奶牛和后缀最小值。

## 主要易错点

1. 先按 `a` 排序，才能把路径相交关系转化为 `b` 序列上的前缀最大值和后缀最小值判断。
2. `a` 和 `b` 属于同一头奶牛，必须用 `Node` 绑定在一起排序，不能分别排序两个数组。
3. 后缀最小值应先初始化 `suffix_min[N - 1]`，再从 `N - 2` 向左计算。
4. 主循环没有考虑第一头奶牛，需要额外判断 `cows[0].b == suffix_min[0]`。
5. `vector<Node> cows(N)` 和 `vector<int> suffix_min(N)` 已经包含 `N` 个元素，应按下标赋值，不要再次 `push_back`，也不要重新声明同名数组。

## 对原始代码的整理

整理版保持了你的结构体、排序、后缀最小值和前缀最大值写法，只做了两处必要调整：

1. 删除输入循环中没有被使用的局部变量 `a`、`b`；
2. 将第一头奶牛的判断改为 `cows[0].b == suffix_min[0]`，避免 `N == 1` 时越界。

## 复习问题

3. 为什么第一头奶牛需要单独判断？
4. 为什么 `a` 和 `b` 应放在同一个结构体中？
