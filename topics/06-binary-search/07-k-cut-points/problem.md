## 题意

长度为 `L` 的木条上有 `n` 个可选切口。从中选择 `k` 个切口，将木条分成 `k + 1` 段，求所有方案中“最短一段长度”的最大值。

## 为什么可以二分答案

假设要求每一段长度至少为 `minimumLength`：

- 如果某个长度可行，那么更小的长度一定也可行；
- 如果某个长度不可行，那么更大的长度一定也不可行。

可行性随候选长度具有单调性：

```text
可行 可行 可行 ... 最大可行值 | 不可行 不可行 ...
```

因此可以二分枚举最短段长度，并寻找最大的可行值。

`k` 个切口会产生 `k + 1` 段，所以最短段不可能超过平均长度：

```cpp
int right = L / (k + 1);
```

使用 `L` 作为右边界也能得到正确结果，但范围更宽。

## 如何判断一个候选长度是否可行

从木条左端 `0` 开始，按照切口位置从小到大的顺序检查。只要当前切口与上一次选择的位置之间的距离不少于候选长度，就选择它：

```cpp
if (position - lastPosition >= minimumLength) {
    lastPosition = position;
    selectedCount++;
}
```

每次选择最靠左的可用切口，会给后面的切口和最后一段留下最多空间。如果这种选择仍无法得到合法方案，改选更靠右的切口不会更好。

切口位置若没有明确保证有序，必须先排序：

```cpp
sort(cutPositions.begin(), cutPositions.end());
```

## 为什么选够 `k` 个切口后停止

这套写法中，`selectedCount` 统计已经选择的切口数量，`lastPosition` 要保存第 `k` 个切口的位置。选够后立即停止：

```cpp
if (selectedCount == k) {
    break;
}
```

停止并不是因为“多选切口一定不允许”。如果能找到更多间距合格的切口，删除多余切口只会合并相邻段，确实仍可得到 `k` 个切口的方案。

这里停止的直接原因是：后面还要使用 `lastPosition` 检查第 `k` 个切口到木条末端的距离。如果继续选择，`lastPosition` 会变成第 `k+1`、第 `k+2` 个切口的位置，不再表示实际方案的最后一个切口。

也可以不中止，但那时应改成统计完整段数或额外保存第 `k` 个切口，不能继续沿用当前变量含义。

## 最后一段不能遗漏

选够 `k` 个切口，只能保证前 `k` 段满足最短长度，还必须检查最后一个切口到终点 `L` 的第 `k + 1` 段：

```cpp
return selectedCount == k &&
       L - lastPosition >= minimumLength;
```

例如木条长 `10`，只需选择一个切口，可选位置只有 `9`。候选长度为 `9` 时，左侧一段长度为 `9`，但最后一段只有 `1`，因此不可行。

## `last` 和 `sum` 为什么在每轮 `while` 中初始化

每次二分得到新的 `middle`，都要从木条左端重新判断一次，因此：

```cpp
int selectedCount = 0;
int lastPosition = 0;
```

必须在每次可行性检查开始时初始化。

如果把它们放到遍历切口的 `for` 循环内部，每检查一个切口都会重新清零，无法保存上一次选择的位置和已经选择的数量。如果放在整个二分循环外，不同候选长度的检查又会互相污染。

正确层级是：

```text
二分产生一个新的候选长度
    初始化 last 和 count
    从左到右遍历所有切口
    判断当前候选长度是否可行
```

## 另一种不中止的计数方式

也可以继续扫描全部切口，把变量定义成“已经得到的合格段数”：

```cpp
int segmentCount = 0;
int lastPosition = 0;

for (int position : cutPositions) {
    if (position - lastPosition >= minimumLength) {
        lastPosition = position;
        segmentCount++;
    }
}

if (L - lastPosition >= minimumLength) {
    segmentCount++;
}

bool possible = segmentCount >= k + 1;
```

这时判断的是 `k + 1` 段，而不是 `k` 个切口。两种方式都正确，但变量含义和最终条件必须成套使用，不能混合。

## 复杂度

- 排序切口：`O(n log n)`；
- 每次可行性检查：`O(n)`；
- 二分检查次数：`O(log L)`；
- 总时间复杂度：`O(n log n + n log L)`；
- 额外空间复杂度：除输入数组外为 `O(1)`。

## 主要易错点

1. 二分的是“最短段长度”，不是切口位置。
2. 切口必须按照从左到右的顺序处理；没有顺序保证时要先排序。
3. `last` 和切口计数应在每次候选长度检查开始时初始化，不能在遍历每个切口时反复清零。
4. 选够 `k` 个切口后，还要检查最后一段 `L - last` 是否达到候选长度。
5. 使用“选够即停止”写法时，最终判断为“切口数等于 `k` 且末段合格”。
6. 使用“扫描到底”写法时，应统计合格段数，并判断段数是否至少为 `k + 1`。
7. 可行时记录当前答案并向右搜索更大值；不可行时向左缩小候选值。
